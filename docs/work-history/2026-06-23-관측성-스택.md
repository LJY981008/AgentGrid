## 의도/목적 — 왜 이 작업을 하나

백테스트 최적화를 반복하는데 측정이 **임시방편**(`time.monotonic()` 수동 타이밍 + `ru_maxrss` 전체 peak)이라 ① phase별 분해 없어 병목을 추측에 의존 ② **peak 11.7GB 원천 미확정**(Python 객체 vs DuckDB C++ 버퍼 — 추측 금지인데 정밀 도구 부재) ③ 최적화 before/after 진척을 기록·비교할 영속 수단 없음. 사용자 요구 = **Prometheus+Grafana 모니터링 장착 + 라운드별 Grafana Local Snapshot + tbbe-hub 식 레이어 대시보드**. 이 스택이 서면 데이터 기반 최적화가 가능해지고, **peak 11.7GB 범인(Python/DuckDB)을 3종 메모리 동시 측정으로 확정**(이 작업의 핵심 목적).
