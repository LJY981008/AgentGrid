# ADR-005: SEC EDGAR 재무 정규화 = 직접 JSON 파싱 (edgartools 미사용)

- **날짜**: 2026-06-18
- **상태**: 승인
- **결정자**: 사용자 / Claude 협의
- **개정 대상**: [[ADR-002-미국-데이터소스-아키텍처]] 의 "재무 = SEC EDGAR **+ edgartools**" 중 정규화 도구 선택 부분(EDGAR 소스 자체·filed=PIT·CIK 생존편향 결정은 유효, 변경 없음).

## 맥락 (Context)

#2 cik resolver(`data/edgar.py` company_tickers→CIK 적재) 완료 → 이제 CIK 로 SEC **XBRL 재무(companyfacts API)**를 적재해 모멘텀 단일 팩터 → 밸류(P/B)·퀄리티(ROE) 멀티팩터로 확장(#재무-1, stock-1st_plan §4.2). ADR-002 는 재무 정규화 도구로 `edgartools`(서드파티 라이브러리)를 지정해 뒀다. 실제 구현 직전 재검토 결과:

- **#재무-1 슬라이스 범위**: 필요한 concept 는 소수 — `us-gaap:StockholdersEquity`(자기자본)·`us-gaap:NetIncomeLoss`(순이익)·`dei:EntityCommonStockSharesOutstanding`(주식수). ROE·P/B 두 팩터만.
- **companyfacts 응답이 단순·안정**: 단일 GET 으로 회사 전 concept 반환, fact 객체 스키마는 평면(`{end, val, accn, fy, fp, form, filed, start?, frame?}`) — 명세 캡처([[../apis/sec-edgar/companyfacts|docs/apis/sec-edgar/companyfacts.json]], 2026-06-18 라이브 실측)로 진실 원천 확보.
- **금융 BLOCKING(룩어헤드)**: PIT 가드는 `filed`(공시일) 기준이어야 정확(분기말 end 기준이면 미래 누설). 이 가드를 **우리 코드가 직접 통제**해야 신뢰 가능 — 서드파티 정규화 계층 안에 묻히면 감사 어려움.
- edgartools 는 ~15+ 필드 광범위 정규화·전 재무제표 추상화를 제공하나, 슬라이스엔 **과대(heavy dep)**이고 그 정규화 동작은 미검증(학습데이터 불신 — tech-researcher 규약).

## 결정 (Decision)

**재무 정규화 = 직접 JSON 파싱 (소수 concept).** edgartools 미사용(의존성 미추가).

- `data/edgar.py` 에 `fetch_companyfacts(cik, identity, *, concepts)` 추가 — httpx 로 companyfacts GET, 지정 concept 의 `units` 배열만 `FinancialFact`(cik·concept·fiscal_period·disclosed_at·value:Decimal) 리스트로 추출. company_tickers fetch 와 동일 패턴(EdgarError 클래스·User-Agent=EDGAR_IDENTITY·httpx).
- PIT 가드는 `rules/_financials.latest_as_of`(disclosed_at=`filed` <= as_of 중 fiscal_period 최신)가 **단일 출처로 코드화** — 룩어헤드를 우리가 완전 통제.
- 저장 = 슬라이스 규모라 `base_dir/edgar/financials.json`(list[FinancialFact] 직렬화·Decimal→str). PG/Parquet 운영 테이블은 결제·운영 후.
- ⚠️ 재무팩터 노출은 ranking factors dict 정보 추가일 뿐 — **결합·가중치 금지(§9-2 백테스트가 결정)**·`meta.validated=false` 불변(검증은 가격 결제+S6 후).

## 검토한 대안 (Alternatives)

| 대안 | 장점 | 단점 | 판정 |
|---|---|---|---|
| **직접 JSON 파싱** (채택) | 소수 concept 완전 제어·PIT(filed) 가드 직접 코드화·의존성 0·companyfacts 스키마 단순·명세 캡처로 환각 차단 | 재무제표 광범위 커버 시 직접 파싱 코드 증가 | ✅ 슬라이스(ROE·P/B)에 최적. 제어·감사·경량 |
| **edgartools** (ADR-002 원안) | 광범위 정규화·전 재무제표 추상화·계산 헬퍼 | heavy dep·~15필드 정규화 동작 미검증·PIT 가드가 라이브러리 내부에 묻혀 감사 어려움·슬라이스엔 과대 | ❌ 현 슬라이스엔 과함. 광범위 커버 필요 시 후속 재검토 |
| 재무 스킵(가격만) | 단순 | 모멘텀 단일 팩터 — 밸류·퀄리티 확장 불가. 결제 전 무료로 할 수 있는 최고가치 작업 포기 | ❌ |

## 결과 (Consequences)

- **얻는 것**: 의존성 미추가(uv.lock 불변). PIT 룩어헤드 가드를 `_financials` 한 곳에서 완전 통제·테스트(sabotage 패턴). companyfacts 명세가 코드 진실 원천(필드 환각 차단). companyconcept 라이브 실측으로 fact 스키마 확정(NetIncomeLoss 연/분기 혼재 등 함정 문서화).
- **감수하는 것**: concept 추가(부채·성장 등) 시 파싱 코드를 우리가 직접 늘림. 재무제표 전체(현금흐름·세부 손익)가 필요해지면 edgartools 재도입 검토.
- **재검토 트리거**: ① 팩터가 ~10+ concept·복합 재무비율로 확장 ② 재무제표 전체 정규화 필요 ③ XBRL 태그 변형(회사별 상이) 처리 부담 급증 — 이때 edgartools(또는 동등 라이브러리) 재평가(PIT 가드 통제권 유지 전제).
