## 추천 조합 (1인 개발·무료 우선)

### (A) 30년 벌크 백테스트 = **FinanceDataReader(주축) + pykrx(보강)**
- **FDR**: KRX 소스로 **1995-05-02~현재** 일봉, 코스피/코스닥/코넥스 + **상장폐지종목(KRX-DELISTING) 별도 제공** → 생존편향 방어의 핵심. 종목마스터(상장/폐지) 일괄 확보.
- **pykrx 보강**: FDR이 약한 **펀더멘털(PER/PBR/EPS/BPS/DIV/DPS)·시가총액·거래대금·투자자별 매매**를 종목×일자로 보충. 분기 재무는 pykrx 펀더멘털 스냅샷으로 근사.
- 두 라이브러리 모두 비공식 스크래핑 → **초기 1회 벌크 적재**에 적합(대량 호출 시 1초 지연·재시도 필수). 적재 후엔 로컬 저장소가 진실원본.

### (B) 일일 증분 갱신 = **KRX OpenAPI(공식, 안정) 우선, pykrx 차선**
- 매일 장 마감 후 **일별매매정보 1콜**로 전 종목 종가/거래량/거래대금 일괄 수신 → 종목별 루프 불필요, 차단 위험 최소.
- 단, KRX OpenAPI는 **2010년 이후만** 제공하므로 (A) 30년 벌크엔 부적합 → 역할 분리가 핵심.
- 차선: pykrx `get_market_ohlcv(날짜, market=...)` 일자 단위 일괄 조회.
- 실시간/장중 데이터·주문 연동이 추후 필요하면 KIS 또는 키움 REST(둘 다 크로스플랫폼) 추가.

## 데이터 규모 → 저장 방식 시사점

- 코스피+코스닥 현행 ~2,800종목, 폐지 포함 누적 추정 **~4,000~5,000종목**.
- 거래일/년 ~245일 × 30년 ≈ **7,350 거래일**.
- 상한 추정: 5,000종목 × 7,350일 ≈ **약 3,675만 행**(종목별 상장기간 차이로 실제는 더 적음, 대략 1,500만~3,000만 행).
- OHLCV+거래대금+시총 한 행 ~80~120 bytes → 압축 전 **수 GB** 수준. 단일 노트북에서 충분히 다룸.

**권고**:
- **백테스트 일괄 스캔 위주** → **Parquet(종목별 또는 연도 파티션) + DuckDB/pandas** 가 가장 단순·빠름·무료. 1인 개발 1순위.
- **서비스 DB로 일일 갱신·조회 혼합** → **PostgreSQL 18** (이미 인프라 보유). 수천만 행은 PG 단독으로 무리 없음. (종목+일자) 복합 PK + BRIN 인덱스.
- **TimescaleDB**는 분/틱 단위 고빈도·연속 집계가 필요할 때 검토. **일봉 3,000만 행 수준엔 과투자** — 현 단계 비권장.
- 실용안: **Parquet(백테스트 분석) + PG(일일 운영·API 서빙) 병행**, Parquet을 1차 적재 산출물로.

## Caveats (반드시 인지)

1. **커버리지 구멍**: KRX OpenAPI 2010~, KIS/키움 일봉 과거 한도 공식 미명시(페이징 100건 단위) → **30년 전체는 비공식 라이브러리(FDR/pykrx)에만 의존**. 공식 단독으로 30년 백테스트 불가.
2. **생존편향(survivorship bias)**: 폐지종목 누락 시 백테스트 수익률 과대. **FDR KRX-DELISTING 반드시 포함**. 아시아도 10년 회고 시 ~25% 종목 누락 가능(일반론).
3. **수정주가(액면분할·배당) 이슈**: 소스마다 수정주가/원주가 정의 상이. FDR/pykrx/야후의 adjusted 정의를 **단일 소스로 통일**하고 액면분할 이벤트 교차검증 필요. 백테스트는 수정주가 기준 권장.
4. **비공식 차단 리스크**: pykrx·FDR은 KRX/네이버 비공식 스크래핑 → 정책 변경 시 무단 중단 가능. 대량 호출에 1초 지연·재시도·체크포인트 필수. **일일 운영의 신뢰선은 공식 KRX OpenAPI**로 두는 게 안전.
5. **yfinance 한국주식**: 정확도·결측 불안정, Yahoo 비공식 차단 빈번, 수정종가 지역편차 → **한국 종목 1차 소스로 비권장**. 해외 종목 교차검증용 보조에 한정.
6. **KIS/키움 계좌 필요**: 공식 API는 증권계좌·앱키 발급 전제. KIS 초당 한도(실전20/모의5), 키움 TR당 ~1req/s → 전 종목 30년 루프엔 비효율(벌크엔 FDR/pykrx가 유리).
7. **미확인 사항**: KRX OpenAPI 일일 호출 한도·일별매매정보 정확 항목(시총 포함 여부)은 인증키 신청 후 상세 페이지에서 실측 필요. KIS/키움 일봉 최대 과거연도 정확값도 실호출 검증 권장.
