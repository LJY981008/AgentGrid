# 폐지종목 ticker→SEC CIK 매핑 판정

## 결론 (TL;DR)

폐지 ticker→CIK 는 **(a) EODHD 로 가능 + (b) SEC 대안으로도 가능** = **블로커 해소**.
폐지 재무 영구 NULL(c) 아님. 단 커버리지 경계(2018년 폐지 분기점·라이선스 약관)는 주의.

**권장 경로 우선순위**:
1. **(주 경로) EODHD Fundamentals 응답의 `General.CIK` 필드** — 이미 ROE/PB 받으러 fundamentals 를 호출하므로 CIK 가 *그 응답에 딸려 온다*. 별도 매핑 호출 불요. 가장 직접적·확실.
2. **(보조/검증) EODHD ID-Mapping API** (`/api/id-mapping?filter[symbol]=...`→`data[].cik`) — 가격만 있고 fundamentals 호출 전 단계에서 CIK 선확보가 필요할 때. 단 폐지 커버리지 명세 미확정 → 라이브 샘플 필요.
3. **(독립 백업) SEC `cik-lookup-data.txt`** — 회사명↔CIK 누적(폐지 포함). EODHD 의존 끊는 무료 영구 경로지만 ticker 가 아닌 **회사명** 기준이라 매칭 공수.

---

## 1. 핵심 사실 — 왜 CIK 만 있으면 되는가

- SEC `data.sec.gov/api/xbrl/companyfacts/CIK{10자리}.json` 는 **CIK 만 알면** 폐지사의 과거 신고를 PIT-correct(각 fact `filed` 필드 ≤ as_of) 로 반환. EDGAR 는 폐지/파산사 filing **영구보존**(1994~), **CIK 재사용 안 함**. (메모리 [[research-sec-edgar-free-financials]] 실측)
- 막힌 지점은 단 하나: SEC `company_tickers.json` = **현재 활성 신고사만** → 폐지 ticker→CIK 부재. 이 한 단계만 외부 소스로 메우면 폐지 재무가 풀린다.

---

## 2. EODHD ID-Mapping API (가설 검증 결과)

캡처 명세 `docs/apis/eodhd/id-mapping-cusip-isin-figi-lei-cik.json` 실측 — **엔드포인트는 실재하고 ticker→CIK 양방향 매핑 제공**.

| 항목 | 값 (명세 실측) |
|---|---|
| URL | `GET https://eodhd.com/api/id-mapping` |
| symbol→cik 파라미터 | `filter[symbol]=AAPL.US` (7종 filter[symbol/ex/isin/figi/lei/cusip/cik] 중 최소 1개 필수) |
| 응답 필드 | `meta{total,limit,offset}` + `data[]{symbol,isin,figi,lei,cusip,cik}` + `links.next` |
| CIK 형식 | `"0000320193"` (10자리 zero-pad 문자열) — companyfacts URL 에 그대로 사용 가능 |
| 페이지네이션 | `page[limit]` (default/max 1000), `page[offset]` |
| 인증 | `?api_token=<KEY>` (.env `EODHD_API_KEY`) |
| 포맷 | `&fmt=json` |
| 콜 소비 | 요청당 1 API 콜 |
| 포함 플랜 | **All-In-One, EOD All World, EOD+Intraday All World Ext, Fundamentals Data Feed, *그리고 Free***. → 우리 구독(EOD All World $19.99) **포함** |

### ⚠️ 미확정점 — 폐지 ticker 커버리지
공식 문서(2026-06-29 r.jina.ai 재확인)·캡처 명세 **모두 폐지/inactive 심볼 커버 여부를 명시하지 않음**. 예시가 전부 AAPL.US 등 활성 종목. → **라이브 샘플로 실측 필요**(§5).

## 3. EODHD Fundamentals `General.CIK` (주 경로 — 더 확실)

캡처 명세 `docs/apis/eodhd/fundamental-data-stocks-etfs-funds-indices.json` 실측:

- `GET /api/v1.1/fundamentals/{SYMBOL}.{EXCHANGE}` 응답의 **`General` 객체에 `CIK`, `EIN`, `IsDelisted`(boolean), `Delisted`(date) 필드 존재** (명세 line 55).
- 즉 ROE/PB 를 받으려 fundamentals 를 호출하면 **같은 응답에서 CIK 가 함께 온다** → 별도 매핑 단계 불필요.
- 웹 교차검증(2026-06-29): EODHD 가 "CIK(Central Index Key)를 general company details 의 일부로 제공"·"IsDelisted/DelistedDate 필드로 폐지 식별" 확인.

### 폐지 fundamentals 커버리지 경계 (BLOCKING)
`docs/apis/eodhd/delisted-stock-companies-data.json` + 웹 교차:
- **2018년 이후 폐지**: Fundamental + Div/Split + EOD 제공 → **CIK·재무 모두 확보 가능**.
- **2018년 이전 폐지**: **EOD only** (Fundamental 없음) → fundamentals 응답 자체가 없어 `General.CIK` 도 못 얻음. **이 구간은 ID-Mapping API 또는 SEC 대안이 필요**.

→ fundamentals 경로는 2018+ 폐지를 깔끔히 풀지만, 2018 이전 폐지의 CIK 는 ID-Mapping(§2) 또는 SEC(§4) 로 보강해야 함. 단 어차피 **XBRL 구조화 재무는 2009~만** 존재하므로(메모리 [[research-sec-edgar-free-financials]]), 2009 이전 폐지사는 CIK 를 얻어도 SEC 재무가 없다. 실질 사각지대는 **2009~2018 폐지 + EODHD fundamentals 미수록** 케이스로 좁혀짐.

## 4. SEC 독립 대안 경로 (EODHD 의존 끊기)

웹 실측(SEC 공식 "Accessing EDGAR Data", 2026-06-29):

### (4-A) `cik-lookup-data.txt` ✅ 실재 확인
> "a current list of all CIKs matched with entity name (13 MB, text file). This list includes funds and individuals and is **historically cumulative for company names**. Thus a given CIK may be associated with multiple names in the case of company or fund name changes, and **the list contains some entities that no longer file with the SEC.**"

- 위치(통상): `https://www.sec.gov/Archives/edgar/cik-lookup-data.txt`
- **폐지/구회사명 포함** (누적). 단 매핑이 **회사명→CIK** 이지 **ticker→CIK 아님** → ticker 를 회사명으로 변환하는 중간 단계(EODHD 폐지목록의 `Name` 필드 등) 필요. 회사명 매칭은 노이즈(법인명 표기 차이) 있음.

### (4-B) Master Index (`master.idx`) ✅
- Notre Dame SRAF 실측: **1993Q1~현재** 분기별, 필드 = `CIK, Company Name, Form Type, Date Filed, Filename`. 전 filer 누적(폐지 포함). cik-lookup 과 동일하게 회사명 기반.

### (4-C) `submissions/CIK{cik}.json`
- CIK 를 이미 알 때 former tickers/names 역추적용. ticker→CIK 의 *역방향*이라 1차 매핑엔 부적합(전수 스캔 필요).

**SEC 대안 한계**: 전부 **회사명 기반**이라 ticker→회사명 브리지가 필요. EODHD `General.CIK`(직접 ticker→CIK)보다 매칭 공수·오차 큼. → SEC 는 **EODHD 가 비는 구간(2009~2018 폐지)·검증·영구 백업**용으로 위치.

## 5. 라이브 샘플 (메인이 실행 — 절차만, 키값 노출 금지)

명세가 폐지 커버리지를 확정 못 하므로 **폐지 ticker ~50개로 실측 필요**. 키는 `.env` `EODHD_API_KEY` (로깅·하드코딩·커밋 금지).

### 테스트 A — ID-Mapping 이 폐지 ticker 에 CIK 반환하나
```bash
# 폐지 티커 예시(검증용): LEHMQ(리먼), WAMUQ(워싱턴뮤추얼), ENRNQ(엔론) 등 .env 키 주입
# (실제로는 우리 유니버스의 IsDelisted=true 50개 샘플 사용)
curl -s "https://eodhd.com/api/id-mapping?filter[symbol]=LEHMQ.US&fmt=json&api_token=${EODHD_API_KEY}"
# 기대: data[0].cik 가 채워지면 폐지 ticker 커버 → ID-Mapping 단독 경로 성립
# data 빈 배열이면 폐지 미커버 → Fundamentals General.CIK 경로로 폴백
```

### 테스트 B — Fundamentals General.CIK (2018+ 폐지)
```bash
curl -s "https://eodhd.com/api/v1.1/fundamentals/{폐지티커}.US?filter=General::CIK,General::IsDelisted,General::Delisted&fmt=json&api_token=${EODHD_API_KEY}"
# 기대: {"CIK":"...","IsDelisted":true,"Delisted":"YYYY-MM-DD"}
```

### 판정 기준
- 우리 유니버스 IsDelisted=true 50,106 중 무작위 50개 샘플로 A·B 실행.
- **A 가 폐지에 cik 반환 ≥ 80%** → ID-Mapping 단독 채택(가장 단순).
- A 가 부족하면 B 의 커버율 측정 → 2018+ 는 B, 2018 이전(또는 B 누락)은 SEC cik-lookup-data.txt 회사명 매칭 폴백.
- 어느 경로든 CIK 확보율을 **연도대별(폐지연도)로 집계**해 사각지대(2009 이전 = SEC 재무 자체 없음) 분리 보고.

## 6. 판정 요약 테이블

| 경로 | 폐지 ticker→CIK 가능? | 커버리지 경계 | 신뢰도 | 비용 |
|---|---|---|---|---|
| **EODHD Fundamentals `General.CIK`** | ✅ (2018+ 폐지) | 2018 이전 폐지는 fundamentals 없음 → CIK 못 얻음 | 명세 확정(필드 실재) + 라이브 권장 | 현 구독 내 |
| **EODHD ID-Mapping `filter[symbol]→cik`** | ⚠️ 추정(엔드포인트·필드 확정, 폐지 커버 미확정) | **라이브 실측 필요** | 명세 확정 / 폐지 커버 추정 | Free 포함(현 구독 OK) |
| **SEC `cik-lookup-data.txt`** | ✅ but 회사명 기반(ticker 직접 아님) | 폐지·구명 누적 포함. ticker→명 브리지 필요 | 공식 확정 | 무료·영구 |
| **SEC companyfacts (CIK→재무)** | — (CIK 입력측) | XBRL 2009~만 | 공식 확정(메모리) | 무료 |

**최종 판정: (a) EODHD 가능 + (b) SEC 가능. (c) 영구 NULL 아님.**
실질 사각지대 = **2009년 이전 폐지사**(CIK 를 얻어도 SEC XBRL 재무 부재) — 이건 CIK 매핑 문제가 아니라 SEC 데이터 커버리지 한계. 다팩터(ROE/PB) 백테스트의 재무 시작점을 2009~로 잡으면 무관.

## 7. Caveats / 미확인

- **[라이브 미검증]** ID-Mapping 의 폐지 ticker 실제 커버율 — §5 테스트 A 로 확정 전까지 추정. 공식 문서·캡처 명세 모두 침묵.
- **[라이선스 BLOCKING]** EODHD 구독 해지/만료 후 **1개월 내 데이터 전량 삭제 의무** (메모리 [[research-eodhd]]) → 폐지 CIK 매핑 테이블도 EODHD 산출이면 합법 영구보관 불가. **CIK 는 SEC 퍼블릭도메인 사실** 이므로, EODHD 로 1회 확보한 ticker→CIK 매핑을 **SEC cik-lookup-data.txt 로 교차검증·재현**해 두면 약관 리스크 회피(CIK 자체는 SEC 공개 데이터).
- **[티커 재사용]** ticker 는 폐지 후 타사 재취득됨(SEC 공식 경고: PALM 사례). 매핑 시 **폐지 시점(Delisted date)·회사명 동시 대조** 필수 — ticker 단독 매칭은 잘못된 CIK 위험(룩어헤드/오염).
- **[회사명 매칭 노이즈]** SEC 회사명 기반 경로는 법인명 표기차(Inc./Corp./공백)로 fuzzy 매칭 오차 — 자동화 시 정밀도 측정 필요.
- **[fundamentals 콜 비용]** EODHD fundamentals 요청은 10콜 추정(메모리 [[research-eodhd]], 본 페이지 미기재) — 50,106 전수 시 콜 예산 확인.
- **유효기한**: API 명세·플랜 포함 여부 6개월 주기 재확인. 2018 분기점·플랜 구성은 시점 민감.
