# S5-a 적재 안전성 선결 — 설계 (다년·전체유니버스 적재 기반)

> 브레인스토밍 산출 설계 문서(2026-06-18). 다음 = writing-plans 로 구현 플랜. EODHD 결제 후 S5(다년·전체유니버스) 의 첫 서브단계.

## 1. Context (왜 S5-a)

EODHD EOD Historical($19.99) 결제 완료 → S5(전체 미국 유니버스·폐지 포함·다년 적재) 잠금 해제. 단 S5 를 단일 스펙으로 벌크 돌리면 **P0 BLOCKING 갭(데이터 소실·생존편향 누수)** 미해결 상태로 돈 걸린 데이터를 오염시킨다. 그래서 S5 를 4분해하고, **벌크 전 반드시 선결해야 할 적재 안전성**을 S5-a 로 먼저 짓는다.

S5 4분해(의존성順):
- **S5-a (이 문서)** — 적재 안전성: PG 스키마(alembic 첫 실사용) + Parquet write 소실 봉인(G1) + 토큰 로거 가드(G6)
- S5-b — 종목마스터 채움: `iter_universe` 실호출 → 유니버스 실측 → `stock`/`ticker_history` UPSERT. expected 원천을 마스터로 전환(G2)
- S5-c — 벌크 오케스트레이션: 유니버스 자동조회→적재 루프(G5)·체크포인트/재시도(G4)·검증 스캔 병목 완화(G8)·Parquet→PG 실벌크 동기
- S5-d — 실 UniversePort 교체(G7)·S6 신뢰성 게이트 전항목 PASS → `meta.validated=true` 전환

## 2. 확정 결정 (사용자 승인)

| # | 결정 | 값 |
|---|---|---|
| D-분해 | S5 분해 | 4분해, S5-a 먼저 |
| D-저장 | 종목마스터 저장 | **PG/alembic**(JSON 아님). ADR-001 첫 실사용 |
| D-테이블 | PG 첫 마이그레이션 범위 | **stock + ticker_history + daily_bar 전부** |
| R1 | stock PK | **surrogate BIGINT id PK + cik nullable UNIQUE** (cik 미해소 폐지·ETF·외국주도 적재 → 생존편향 누수 0) |

## 3. 아키텍처 / 컴포넌트

### 3.1 PG18 스키마 (alembic 첫 마이그레이션 1개 — `create_core_tables`)

> 정밀도는 `data/storage.py` decimal128(가격 38,10 · adj_factor 38,12)과 **정확히 일치**(무손실 동기). PG18 고급기능(파티션·BRIN·ENUM·CHECK)은 alembic `op.execute()` raw SQL.

**`stock`** (종목마스터 — 폐지 포함 합집합, DELETE 금지)
- `id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY` (surrogate — R1)
- `cik TEXT NULL UNIQUE` (EDGAR 매핑. EODHD 미제공·현재스냅샷만이라 폐지·ETF·외국주 다수 NULL — 생존편향 위해 NULL 허용)
- `ticker TEXT NOT NULL`
- `name TEXT`
- `exchange exchange_enum NOT NULL` (Exchange 6값 ENUM. ⚠️ EODHD 는 US 통합코드만 — 정밀 NYSE/NASDAQ 구분 약함, 보수적 분류)
- `listed_at DATE NULL` · `delisted_at DATE NULL` (NULL=현재상장. 폐지는 이 컬럼으로만 표현 — DELETE 금지)
- `delisted_at_source TEXT NULL` (폐지일 출처. EODHD 폐지일 미제공 → "마지막 EOD 거래일 추론" 등 근거 기록)
- `source TEXT NOT NULL` · `ingested_at TIMESTAMPTZ NOT NULL`
- 인덱스: UNIQUE(cik) WHERE cik IS NOT NULL, INDEX(ticker)

**`ticker_history`** (시점별 ticker↔cik — 폐지 후 ticker 재사용 정답, 현 `EdgarSnapshotResolver` 한계 메움)
- `stock_id BIGINT NOT NULL REFERENCES stock(id)`
- `ticker TEXT NOT NULL` · `cik TEXT NULL`
- `valid_from DATE NOT NULL` · `valid_to DATE NULL` (NULL=현재)
- PK(`stock_id, ticker, valid_from`)
- PIT 조인 규약: `valid_from <= trade_date < valid_to`(또는 valid_to IS NULL)
- ⚠️ 구간 중첩 금지(EXCLUDE btree_gist)는 **S5-b 채움과 동반 이월**(스키마는 S5-a, 데이터 무결성 제약은 채울 때)

**`daily_bar`** (일봉 — Parquet 1차 진실원본의 PG 파생 서빙본)
- `ticker TEXT NOT NULL` · `trade_date DATE NOT NULL`
- `open/high/low/close NUMERIC(38,10)` · `volume BIGINT` · `value BIGINT NULL` · `adj_factor NUMERIC(38,12)`
- `source TEXT NOT NULL` · `ingested_at TIMESTAMPTZ NOT NULL`
- **PK(`ticker, trade_date`)** · **PARTITION BY RANGE(`trade_date`)** 연도별
- CHECK: OHLC 정합(high>=low 등) · 양수 가격(open/high/low/close>0) · adj_factor>0 — **`storage.py` DuckDB 게이트와 1:1 동형(PG=2차 방어선)**
- BRIN(`trade_date`) · DEFAULT 파티션(안전망)
- **daily_bar→stock 직접 FK 안 함**(D2 — ticker 시변 N:1·벌크 COPY 성능·1인 운영). 고아 ticker 는 사후검증 쿼리로 탐지

### 3.2 alembic 통합

- 의존성: `uv add alembic psycopg[binary]` (**psycopg3** — psycopg2 아님). uv.lock 실측 고정.
- 디렉토리: `/migrations/`(src 밖 — 인프라). `alembic.ini`·`env.py`·`versions/`.
- `env.py`: compose 의 `DATABASE_URL`(또는 PG 접속 env)을 읽어 `postgresql+psycopg://` 로 변환. **alembic.ini 패스워드 하드코딩 금지**(env 주입).
- ⚠️ compose `app` 서비스 volumes 에 `./migrations` 마운트 추가 필요(현재 없음 — 실측).
- 실행: `docker compose exec app alembic upgrade head` / 다운그레이드 `downgrade -1`(재현성).
- 마이그레이션 1개(create_core_tables) — 3테이블 + ENUM + 파티션 + CHECK + 인덱스를 op.execute raw SQL 로.

### 3.3 G1 — Parquet write read-merge-write 전환 (BLOCKING)

현 `write_daily_bars`는 `(ticker, year)` 통파일 **덮어쓰기** → 다년 적재는 본질적으로 연도분할 호출이라 같은 연도 부분호출 시 이전 행이 **조용히 소실**(expected 대조도 다른 배치라 미탐지).

전환: **read(기존 파일) → merge(신규+기존, `(ticker, trade_date)` dedup·신규 우선) → write(temp 파일 → atomic rename)**. expected 검증은 **병합 후 전체** 기준.

### 3.4 G6 — httpx 토큰 로거 가드

EODHD 토큰이 URL 쿼리(`?api_token=`)에 실림 → httpx 로거가 URL 로깅 시 노출. 가드: httpx 로거 레벨 WARNING + URL 의 `api_token` 값 redact(로깅 직전 마스킹). 벌크 로깅(S5-c) 전 필수.

### 3.5 D5 — Parquet↔PG 단방향 동기 (메커니즘 설계만, 실벌크=S5-c)

- **단방향**: Parquet(1차 진실원본) → PG(파생 서빙). PG 직접 수정 금지(역류=오염).
- 메커니즘: DuckDB 스캔 → PG `COPY`/`INSERT ... ON CONFLICT(ticker,trade_date) DO UPDATE`(PK 기반 멱등 UPSERT).
- 주기: 일 1회 충분(랭킹은 배치). ⚠️ 경계: **S5-a 는 동기 함수 구현(소량 멱등 테스트)까지**, 전체 유니버스 벌크 동기 실행은 S5-c.

### 3.6 데이터 흐름 — 벌크 적재 순서 (BLOCKING 안전 순서)

```
fetch(EODHD) → write_daily_bars(G1 read-merge-write) → verify_parquet(expected=병합결과)
   → PASS 시에만 → Parquet→PG 동기(UPSERT) → PG 사후검증(고아 ticker)
```
⚠️ Parquet 게이트 FAIL 시 **PG 미반영**(stale 이 손상보다 안전 — Parquet 가 진실, PG 는 그 복제).

## 5. 금융 BLOCKING 가드 (스키마·코드에 반영)

- **생존편향**: stock 폐지 포함·DELETE 금지(폐지=delisted_at)·cik NULL 허용(미해소 폐지종목 적재). ticker_history 로 시점별 ticker 재사용 해소.
- **수정주가**: daily_bar 원주가 + adj_factor 분리(원본 불변)·Decimal 정밀(storage.py scale 일치).
- **룩어헤드**: daily_bar trade_date 키. PIT 조인은 호출부 계약(ticker_history valid_from/to).
- **소실 봉인**: G1 read-merge-write + 벌크 안전 순서(Parquet PASS 후에만 PG).
- **CHECK 2차 방어선**: PG CHECK = DuckDB 게이트 동형(이중 방어).

## 6. 에러 처리

- alembic 마이그레이션 실패 → 명시적 중단(부분 적용 방지 — 트랜잭션). 
- PG 동기 실패 → Parquet 는 이미 PASS·불변이므로 재시도 가능(멱등 UPSERT). 동기 실패가 Parquet 진실을 훼손 안 함.
- G1 write: temp→rename atomic — 중간 실패 시 기존 파일 보존.
- 실패 명확 보고(python-conventions): 조용한 소실·추측 채움 금지.

## 7. 테스트 전략

- **G1 회귀(BLOCKING)**: 같은 (ticker, year) 를 두 번 부분 호출(다른 행) → 병합 후 두 호출 행 모두 보존·dedup 정확. 소실 0 단언(이게 핵심 회귀 봉인).
- **G6**: 토큰 포함 URL 로깅 시 응답·로그에 토큰 미노출.
- **PG repo**: stock UPSERT(cik NULL 종목 적재·중복 cik 충돌)·ticker_history PIT 조인·daily_bar UPSERT 멱등(같은 PK 재동기 무변화). testcontainers 또는 compose postgres 대상(라이브 EODHD 0).
- **CHECK 동형**: PG CHECK 가 DuckDB 게이트와 같은 위반(음수가격·OHLC 부정합·adj<=0) 거부.
- **마이그레이션**: upgrade→downgrade→upgrade 재현성.
