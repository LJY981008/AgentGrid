> 기획 문서는 버전 넘버링으로 추가 — 기존 파일 덮어쓰기 금지.

| 문서 | 상태 | 요약 | 다음 단계 |
|---|---|---|---|
| [1st_plan.md](1st_plan.md) | 초안 | 비전·핵심 가치·Phase 1~3 기능 범위·기술 스택·마일스톤 | 구체화 필요: MVP 기능 명세, 신뢰성 지표 정의(무엇을 어떻게 측정해 A~F 산출), 수집 파이프라인 대상/주기, DB 스키마 |

## 미해결 질문 (기획 구체화 대상)

1. **신뢰성 지표 산출 방식** — 정적 분석으로 무엇을 검사? (예외 처리/타임아웃/재시도/서킷 브레이커/멱등성 각각의 판별 기준과 가중치)
2. **수집 대상** — 어떤 소스에서 MCP 서버/플러그인 목록을 가져오나 (GitHub topic? 기존 레지스트리 API? 수동 등록?)
3. **분석 대상 언어 범위** — MCP 서버는 TS/Python 이 다수 — 정적 분석기 1차 지원 언어
4. **사용자 기능 범위** — MVP 에 로그인/리뷰 포함 여부 (기획서엔 "사용자 리뷰" DB 언급 존재)
5. **등급 산정의 공정성** — 자동 분석 한계 고지 방식, 이의 제기 채널
